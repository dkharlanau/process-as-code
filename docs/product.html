Process as Code

Put the business process under the same kind of review as code: a small process contract that can be validated, compared semantically, checked for impact, governed by policy, rendered for people, and exposed safely to agents.

The wedge is not process drawing. It is controlled process change: review the meaning of a change before it becomes a delivery problem.

Why it exists

Process models are useful, but projects also need version history, meaningful diffs, ownership, controls, impact, regression scope, and machine-readable context. Those concerns are usually scattered around the model.

01

Review meaning, not XML

Semantic diff focuses a pull request on changed steps, transitions, roles, systems, controls, risks, and evidence.

02

Connect change to work

Impact analysis and generated test scope turn process change into concrete delivery and regression consequences.

03

Publish from one source

Generate Mermaid, BPMN, RACI, docs, JSON-LD, catalogs, and governed agent context without maintaining parallel descriptions.

A process becomes a change-control object

The YAML/JSON contract remains small enough to review while carrying the links needed for enterprise delivery.

Ten-minute loop

process-code validate examples/customer-creation.process.yaml --strict
process-code diff examples/customer-creation.process.yaml \
  examples/changes/customer-creation-v2.process.yaml
process-code impact examples/customer-creation.process.yaml \
  examples/changes/customer-creation-v2.process.yaml
process-code policy examples/customer-creation.process.yaml \
  --policy examples/policy.yaml

Designed for coexistence

Process as Code complements BPMN editors, modeling suites, and process-mining tools. It adds a Git-native contract and review layer around the process instead of trying to become another authoring suite.

Not a workflow engine and not a replacement for full BPMN modeling. Use it where process intent has to participate in version control, CI, impact analysis, and agent context.

Where it connects

A process can resolve specialist contracts rather than duplicating them. Resolution preserves traceability; each specialist tool still validates its own semantics.

Interface as Code →Reference the operational integration invoked by a process step.Reconciliation as Code →Link process or cutover gates to executable assurance controls and evidence.Decision Tables as Code →Reference the governed rule semantics behind a decision step.
Agent entry point

Governed process context for agents.

The process contract can expose selected steps and allowed actions. MCP and drafting-context commands make the same reviewed process available to agents without turning documentation into an unrestricted tool surface.
